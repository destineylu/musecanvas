# NAS 多人隔离

用户要求每个人输入自己的账号，不能混用。当前账号池、浏览器 profile 和模型配置属于实例级状态，因此选择每人一个内置私有 Muse 引擎的独立容器，而不在共享池上仅增加前端登录。每人独立数据库、文件、模型密钥、Muse Cookie、浏览器 profile、JWT、服务密钥和 Compose 网络；内置引擎不发布端口。

新增 ACCESS_MODE=account，仅接受实例指定邮箱登录，禁止本机免登录 token 和注册；含其它用户的旧库拒绝启动，避免误迁移。HTTPOnly 同站 Cookie 用于登录后媒体加载，媒体按所有权检查并禁止共享缓存。添加退出入口、来源检查和登录节流；桌面 ACCESS_MODE=local 保持原有行为。

NAS 生成器每人生成独立配置和随机凭据，拒绝覆盖；只在忽略目录中保存凭据。默认每实例生成并发 1，平台 / 浏览器分别有资源限制。文档明确每人不同入口，不是单网站内多账号；共享 ComfyUI GPU 尚无跨实例调度，NAS 实际构建运行仍需机器验证。

测试：双实例不同 JWT、上游服务、数据卷，验证跨实例账号与 token 不通、配置不共享、上传 / 媒体不可匿名或跨账号读取、旧免登录 token 被拒、退出清 cookie、生成与账号查询分别发往自己的服务；生成器唯一凭据、网络与卷目录；浏览器登录 / 刷新 / 登出；原桌面模式回归。
