> 普通用户请下载 GitHub Releases 的 `musecanvas-windows-x64.zip`，完整解压后双击 `start.cmd`。包内自带 Node.js、Python 和应用依赖，无需 Docker；首次启动自动创建本机配置，无需注册。双击 `stop.cmd` 停止程序。NAS 章节仅供公司内部部署管理员参考。

# musecanvas v1.0 使用说明

程序内入口：侧栏「使用教程」，或画布底部问号。教程分为基本操作、快捷键、图片工具、创作流程、接入与排错。

## 1. 打开程序

Windows 本机在 PowerShell 执行：

```powershell
Set-Location -LiteralPath 'F:\程序\musecanvas'
.\start.ps1
```

访问 `http://127.0.0.1:8787/`。桌面 `ACCESS_MODE=local` 免登录，沿用本机工作区。更新前端用 `.\start.ps1 -Build`；后端代码更新需先等待任务完成，再执行 `.\stop.ps1` 和 `.\start.ps1`。服务就绪后刷新页面。

NAS `ACCESS_MODE=account` 必须用管理员分配的独立入口、邮箱和密码登录。每人一组独立容器，分别保存账号池、Cookie、浏览器资料、模型配置和文件；进入后可在「设置 → 账号」修改密码。具体部署见 [NAS 部署说明](../deploy/nas/README.md)。

## 2. 选择接入与模型

「设置」集中管理接入方式、模型配置和主题；NAS 登录后还显示账号设置。

| 用途 | 设置位置 | 画布中的用途 |
| --- | --- | --- |
| Muse 的 API Bridge / muse2api | 接入方式 | 对应类别的默认模型选 Muse 时使用 |
| 语言模型 | 模型配置 → 默认语言模型 | 对话、AI 搭建与导演台 AI 布景 |
| 图片模型 | 模型配置 → 默认图片模型 | 图片节点及图片生成工具 |
| 视频模型 | 模型配置 → 默认视频模型 | 视频节点 |
| 本地 ComfyUI | 添加图片 / 视频模型 → ComfyUI 协议 | 运行绑定的工作流并回传结果 |

API Bridge 填本人的服务地址、文件服务地址和 Bearer 密钥。muse2api 可从设置进入「账号池与浏览器绑定」，导入自己的 Muse Cookie；NAS 不继承电脑浏览器的登录状态。

外部模型填写名称、Base URL、模型 ID、API Key 和协议，保存后再选为对应默认模型。兼容范围为 Chat Completions、Images generations/edits、OpenAI Videos multipart 和兼容视频 JSON 任务接口；私有协议可能需要额外适配。密钥留空保留已有值，连接测试不会提交生成任务。

默认选择自动保存，用于新任务。已启动的一键流程固定使用启动时的模型与提示词；执行中不要编辑或删除其模型配置，否则后续步骤会明确失败。

## 3. 从画布生成

1. 新建项目与画布，或进入「独立画布」。
2. 添加文本、图片或视频节点，拖动两侧圆点建立连线。
3. 点击图片 / 视频节点内的「编辑并生成」，填写提示词、比例和视频时长。
4. 文本连入生成节点作为提示词；图片连入作为参考图。参考图必须先生成完成，数量不能超出所选模型支持范围。
5. 点击发送箭头或按 Ctrl+Enter。到「任务」看状态，到「历史」看参数、结果和错误。

常用依赖是「角色提示词 → 角色参考图 → 各镜头图片 → 各自视频」，不同镜头分别分支。不要把上一个镜头的视频接到下一个镜头的文本。

## 4. AI 搭建、分镜与一键生成

「AI 搭建」描述故事、镜头数、角色和风格，生成方案后先预览，再应用到画布。应用只追加节点、连线和分镜表，不自动提交图片 / 视频任务。

「分镜表」可编辑场景、动作、角色、运镜、对白、提示词、时长及比例，支持 CSV 导入 / 导出。点击「生成画布节点」创建文本、图片、视频依赖组；再次点击会追加新节点。

核对节点后点击右上角「一键生成」。默认流程并发 2，可选 1–3；实际并发仍受全局、模型及 Bridge 上限约束。已完成素材跳过，素材节点不重新生成。参考图完成后才派发镜头图，某镜头图完成后即可生成它的视频。

- 暂停：停止派发新步骤，已提交任务继续。
- 继续：恢复后续派发。
- 停止：取消尚未提交的步骤，已提交任务继续完成。
- 失败：阻断依赖它的分支，独立分支继续。核对上游任务后修正并再次一键生成，补齐未完成部分。

关闭页面不停止后台。应用重启后，已有可恢复任务 ID 的任务继续查询；提交中断、结果未知时不自动重发。不要对结果未知的任务反复提交。

## 5. ComfyUI 本地生成

1. 启动 ComfyUI，设置服务地址。本机通常为 `http://127.0.0.1:8188`，不加 `/v1`；NAS 连接另一台电脑时填那台电脑的局域网地址。
2. 添加图片 / 视频模型，选择「本地 ComfyUI 工作流」。导入 API 格式 JSON，或选择本机已保存的工作流。普通界面 JSON 需先在 ComfyUI 开发者模式导出为 API 格式。
3. 绑定画布正向提示词、负面提示词、参考图、宽高、种子，以及需要的时长 / 帧率 / 帧数。自动建议需人工核对，尤其正向与负向文本。
4. 指定 SaveImage、SaveVideo 或 VideoCombine 等最终输出节点；视频启用保存并输出 MP4 / WebM。
5. 保存并测试连接，再选为默认图片 / 视频模型。先跑小尺寸、短时长任务确认模型与显存可用。

只有绑定的参数会替换工作流输入。宽高按基础像素面积与画布比例计算；视频帧数按时长 × 帧率附近满足步长 / 余数规则的值取整，并受最大帧数限制。同一 ComfyUI 实例在一个 musecanvas 工作区内共用一个在途槽位；多个 NAS 工作区共享 GPU 时没有跨实例统一调度器。

当前本机已配置 SD1.5 文生图与参考图工作流供选择。实际出图、参考图上传及 MP4 保存回传已验证；视频导出链路测试不代表所有大型 AI 视频模型已验证。

## 6. 素材、历史与导演台

- 素材库：上传、已完成生成和导演台导出自动归档；支持搜索、类型筛选、收藏、标签及加入其它画布。
- 生成历史：复用提示词、插入旧结果，或应用到选中的同类型节点。
- 画布版本：生成、应用流程、整理及回退前自动备份；每张画布最多保存 80 个版本。等当前任务完成后再恢复版本，恢复前也会备份。
- 自动整理：按依赖层级排列节点并适配视口，保留内容和素材；可在历史中回退。
- 3D 导演台：摆放人物和道具，在时间轴上记录姿势 / 镜头变化；保存场景后可继续编辑。导出视频得到人偶预演；导出关键帧到画布，连接到生成节点后可制作最终画面。导演台时间轴不会自动传给生成模型。
- 删除：节点标题旁或底部「删除」，也可按 Delete；移除节点及相关连线，已归档素材仍保留。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 本机显示「未登录 / 重新连接」 | 先点重新连接，再 Ctrl+F5；确认后端已就绪且使用本机地址。更新期间版本或启动时序不同步是可能原因，不能只凭提示判定账号失效。 |
| NAS 无法登录 | 核对个人工作区入口、邮箱和密码；会话过期后重新登录。HTTPS 的 PUBLIC_BASE 和 Cookie 设置需与入口一致。 |
| NAS 能打开程序，但账号检测未确认、周额度为空，或生成提示 Still sending / Delivery not confirmed | 工作区网页连通与 NAS 出站访问 Muse 是两条链路。检查 NAS / 容器的 Muse HTTPS 与长连接出口；Windows 的代理不会自动作用于 NAS。网络超时不能判定 Cookie 失效。先恢复 NAS 出口，再检测账号、查询额度并重试失败节点。 |
| Muse API 可连，但 Cookie 浏览器会话仍失败 | API Bridge 成功不能证明浏览器链路成功。浏览器需要同时访问 `muse.ai` 和 `hatch.metaaivm.com`；代理规则应覆盖 `DOMAIN-SUFFIX,muse.ai` 与 `DOMAIN-SUFFIX,metaaivm.com`，并使用已验证可分配会话的出口。`/api/session` 返回 `assigned` 与真实生成取得附件应分别验证。 |
| 账号显示可用，但备注显示保活 / 测试未确认 | 「可用」可能保留自上次已确认的账号状态，不能证明当前网络可用。检测按钮会显示本次实际结果；周额度为空表示尚未取到有效额度数据。 |
| 连接成功但生成失败 | 查任务实际错误，再检查额度、协议、模型、尺寸、时长与参考图。连接测试不等于真实生成测试。 |
| 提示缺少供应商 API Key | 到对应模型配置检查密钥；Muse 账号 Cookie 与外部模型 Key 不能互相替代。 |
| ComfyUI 没有输出或模型报错 | 检查已安装模型 / 节点、API 工作流绑定、输出节点及保存开关；先降低尺寸与帧数。 |
| 一键生成一直等待 | 检查依赖参考图状态和并发槽位；失败的上游会阻断其下游。 |
| 后续图片 / 视频因等待超时失败 | Muse 图片和视频默认各有 30 分钟生成预算，排队另有 30 分钟预算，不挤占实际生成时间；客户端会覆盖排队与生成预算并优先取回已完成结果。失败后重新点击一键生成，只生成缺少结果的节点，保留已有素材并按依赖顺序执行。 |
| 提交后停在新线程页面，或模型先回复已生成但还没有附件 | 页面地址、停止按钮消失和模型文字不能证明任务失败或成功。程序会继续等待真实媒体附件，遵循生成时限；明确拒绝、额度不足、认证或送达失败仍会单独报错。 |
| 停止后仍有任务运行 | 停止只取消后续派发，已经提交的任务继续完成。 |

重新连接和刷新不会删除画布或重新提交生成任务。持续故障查看 `server/server.log`、`server/server.err.log`，NAS 查看对应容器日志；不要直接删除数据目录排查。

## 8. 在其它程序调用 muse2api

同机客户端可填写 `http://127.0.0.1:18610/v1`，使用 muse2api 自己的密钥；对话模型 `muse-spark`，图片 `muse-image`，视频 `muse-video`。图片 / 视频需要客户端支持对应接口和任务查询，建议超时至少 600 秒。

也可经 musecanvas 的 `/v1` 兼容接口调用，但此时使用 musecanvas 签发的 API Key；两种密钥不能混用。NAS 独立部署不公开 muse2api 端口，外部调用只接入本人的工作区地址与平台 API Key。对外 `/v1` 当前按 Muse 接入方式转发，不等同于转发设置中所有外部模型或 ComfyUI 工作流。

### 将自己的 Muse Cookie 账号用于 harness

1. 登录自己的工作区域名，在「设置 → 接入方式」选择 **muse2api**。
2. 打开账号池，粘贴自己的 Muse Cookie 并检测，通过后将该账号勾选为参与调度。
3. 打开「设置 → API」，复制 Base URL，创建并复制自己的 API Key。此 Key 是外部访问反代的凭据，Cookie 由工作区内部使用，不要把 Cookie 填进 harness 的 API Key。
4. Harness 选择 OpenAI 兼容 Chat Completions：Base URL 为 `https://你的工作区域名/v1`，模型为 `muse-spark`，API Key 为上一步创建的密钥。启用流式响应，超时建议至少 600 秒。
5. 可通过 `GET /v1/models` 检查认证和模型列表；这不代表 Cookie 已有效，也不代表真实对话已经测试。实际对话调用 `POST /v1/chat/completions`；Responses 也有兼容适配，但具体 harness 的工具调用需要单独验证。

调用路径：**harness → 个人 HTTPS 工作区 `/v1` → 该工作区内置 Muse 引擎 → 本人的 Cookie 账号**。不需要对外开放引擎的 18610 端口，也不使用 API Bridge 的密钥。切换接入方式到 API Bridge 后，`/v1` 将随之改走 Bridge；使用 Cookie 账号时应保持 muse2api 接入。

密钥可随时在设置中删除，删除后立即失效。每个域名的账号、Cookie、密钥和生成数据分别保存，不要跨工作区复制密钥。

### Windows 启动端口

启动脚本读取 `server/.env` 中的 `PORT`，默认 8787。若端口绑定报 `EACCES`，先排查系统或安全软件限制，也可改成可用端口（例如 `PORT=8788`）后重新运行 `start.ps1`。以启动脚本输出的入口地址为准；无需改动 NAS 域名与端口。
