# musecanvas 创作画布

musecanvas 用节点画布组织文字、图片和视频。对话和生成可通过 API Bridge 或原有 muse2api 账号池。已有项目、画布、积分流水和本地素材继续由 `server/data` 保存。

## Windows 本机启动

使用 Node.js 24。接入内网 Bridge 时先连接 Tailscale。

```powershell
Set-Location -LiteralPath 'F:\程序\Mua'
.\start.ps1 -Build
```

打开 `http://127.0.0.1:8787/` 即可进入本机工作区，无需注册或登录。首次进入沿用当前浏览器原身份；没有原会话时优先使用已有项目最多的身份，并固定为本机工作区。原项目和素材保留。后续运行 `.\start.ps1` 即可。Bridge 模式由 musecanvas 内置管理节点、排队和下载。`-Dev` 会额外启动 Vite 端口 `5173`。`.\stop.ps1` 停止由启动脚本启动的 musecanvas 服务。

第一次部署时，按 `server/.env.example` 配置 `server/.env`。`JWT_SECRET` 至少 32 个字符，初始管理员密码至少 12 个字符。已有实例保留原登录签名密钥和管理员配置。

## 设置与上游配置

侧栏底部「设置」集中管理「接入方式」和「主题」。画布右上角也可打开设置。主题提供浅色、深色和跟随系统，立即生效并保存。本机会话可修改连接设置，免登录会话仅在本机回环地址签发和使用；注册接口已关闭。

在「设置 → 接入方式」点击「切换到 API Bridge」或「切换到 muse2api」，新任务立即生效，无需重启。切换前检查目标连接及鉴权，失败时保持原方式。本机默认 muse2api 未运行时自动启动。已有任务继续使用提交时的上游，两种上游的任务可同时完成。

选择保存到 `server/data/upstream.json`，下次启动自动恢复。未保存时使用 `MUA_UPSTREAM` 默认值。命令行 `-Upstream` 仍可覆盖本次启动，但日常切换直接在设置页面进行。

使用 muse2api 时，`MUSE_BASE` 默认是 `http://127.0.0.1:18610`，`MUSE_KEY` 填上游的 `MUSE2API_KEY`。本机默认地址可由启动脚本启动 `upstream/muse2api`，其配置在 `upstream/muse2api/.env`。两种启动模式下均可从「设置 → 接入方式 → muse2api 设置与测试」查看连接、测试鉴权和进入账号池，继续导入账号、绑定浏览器、查看额度和管理调度。管理员可独立保存 muse2api 地址与密钥到 `server/data/muse2api.json`，优先于环境变量并立即生效，密钥留空保留原值。画布的新任务使用设置页选中的接入方式。

在「设置 → 接入方式」页添加 Bridge，填写 API 地址、文件服务地址和 Bearer 密钥。每台 Bridge 默认并发为 1。页面提供模型映射、超时重试、健康检查和最近请求记录。

节点和密钥保存在 `server/data/bridges.json`。管理 API 仅返回密钥是否已设置。模型映射默认将 `muse`、`muse-image` 和 `muse-video` 转换为上游 `muse`。可为模型限定节点，未限定时使用所有启用节点。编辑节点时密钥留空会保留原值。

内置调度器直接连接远端 `/v1/chat/completions`。对外接口继续提供 `/v1/models` 和 `/v1/chat/completions`，使用 Mua 签发的 API Key。生成期间发送 SSE 心跳，上游请求结束后释放节点。文件通过本程序的 `/bridge-media/` 代理下载，已下载素材保存在本机。

API 地址示例为 `http://100.x.x.x:8080/v1`，文件地址为 `http://100.x.x.x:8081`。「测试」检查健康、模型鉴权和文件服务。调度器会跳过不健康和忙碌节点，并按配置重试。所有已登录用户都可在「接入方式」查看 Bridge 节点、模型映射、调度设置和请求记录，并在「测试台」测试对话、图片及视频。修改节点、密钥和调度配置需要管理员账号。

## 画布工作流

- 用底部工具条添加文本、图像、视频和参考图节点。把文本节点连到生成节点可拼入提示词。API Bridge 每个任务支持一张图片参考，muse2api 支持最多三张。
- 右上角「任务」显示当前画布各生成节点的状态，点列表中的任务可定位到节点。任务经排队、Bridge 生成和下载后保存到本机素材库。
- 右侧 Muse 对话支持图片、Markdown 与纯文本，回复可以插入画布。PDF 和 Word 内容可先转换为文本。
- 失败任务按现有积分规则退还。重启后已排队的任务和已经拿到下载地址的任务会继续处理。请求已提交但缺少可恢复结果的任务会标记失败，以防重复生成。

## 创作工作台（v1.0）

画布右上角新增「素材库」「历史」「AI 搭建」「分镜表」「整理」。

- 素材库自动收录当前本机身份上传的图片、视频，以及已完成的生成结果。支持搜索名称/提示词/标签、类型筛选、收藏、改名、标签和跨画布插入；侧栏的「素材库」提供独立浏览与上传入口。
- 历史页分为「生成历史」与「画布版本」。可以复用旧提示词、把旧结果作为素材加入画布，或先选中同类型节点再应用旧结果。生成前、自动整理前、应用流程前及回退前均保存检查点；普通编辑自动分段记录版本，每个画布最多保留 80 个版本。恢复画布前需等待该画布生成任务完成。
- AI 搭建使用当前选择的 Muse 接入方式，输入要求后生成节点与分镜方案；预览后点击应用，追加节点及连线，不覆盖已有内容，也不自动提交媒体生成。
- 分镜表可编辑场景、角色、动作、景别/运镜、对白、提示词、时长及比例，自动保存；支持 CSV 追加导入与导出。点击「生成画布节点」为每个有效镜头创建文本、图片、视频节点并连接。随后先生成镜头图片，再生成对应视频。
- 自动整理按连线方向从左到右排列；没有连线时按网格排列。保留全部节点内容、素材与连线，并自动适配视口。可从历史中的「自动整理前」版本回退。

新增数据位于原有 `studio.db` 的 `canvas_versions`、`asset_notes` 表，分镜保存在画布文档中。已有素材文件继续保留。

验证命令（在 server 目录）：`node --test tests/canvas-workflow.test.mjs`。完整 HTTP 与浏览器验证：`node tests/workbench.integration.mjs`，需本机安装 Google Chrome，使用独立临时数据库和模拟上游，不修改现有项目。


### 外部模型与一键生成

在「设置 → 模型配置」分别添加语言、图片、视频模型，填写 Base URL（含版本前缀）、模型 ID、API Key 和协议。保存后在对应默认模型下拉框选择，立即用于新任务。语言模型用于对话及 AI 搭建；画布图片、视频分别使用所选模型。Muse 与原有 API Bridge / muse2api 接入保留。密钥只保存在被 Git 忽略的 `server/data/models.json`，接口返回时脱敏。

支持 Chat Completions、Images generations/edits、OpenAI Videos multipart，以及返回任务 ID / 状态 / URL 的兼容视频 JSON 接口。高级参数可配置接口路径、附加参数、比例尺寸映射、时长选项。不是所有厂商的私有协议都兼容；「测试连接」只核对模型列表，不发起收费媒体任务。

画布右上角「一键生成」按依赖调度未完成的图片和视频，默认最多同时执行 2 步，可选 1–3；全局任务槽位（默认 3）、Bridge 节点上限和外部模型上限继续约束实际并发。角色参考完成后再生成镜头图，各镜头图完成后再生成对应视频。已完成素材跳过；失败阻断依赖分支，独立分支继续。可暂停、继续、停止后续派发，已提交任务不会被假装取消。

流程状态持久化；关闭页面后台继续运行。程序重启后异步任务可凭任务 ID 续查；提交中断且结果未知时明确报错，不自动重发。流程固定启动时的模型、提示词与连线，修改设置仅影响新流程。执行前自动备份画布。查看程序内「使用说明 → 创作流程」获取完整步骤。


### 本地 ComfyUI

「设置 → 模型配置」添加图片 / 视频模型，选择「本地 ComfyUI 工作流」，地址填写 `http://127.0.0.1:8188`（不加 /v1）。导入 API 格式工作流 JSON，或选择本机 Codex ComfyUI 库中已保存的工作流。确认提示词、参考图、种子、宽高、时长 / 帧数 / 帧率绑定及输出节点，保存、测试后设为对应默认模型。普通界面格式需在 ComfyUI 开发者模式中导出为 API 格式。

工作流可使用任意已安装节点与模型；连接测试检查节点及固定枚举选项，实际显存和模型加载仍需真实生成验证。宽高依据画布比例与基础像素面积计算；视频帧数可设为 4N+1 等规则并限制最大帧数。只有显式绑定的输入才会替换，未绑定的设置保留原工作流。参考图自动上传到 ComfyUI，最终图片和 MP4 / WebM 视频通过 history/view 回传并自动归档。

同一 ComfyUI 服务地址的图片和视频配置共享一个在途任务槽位；不会调用全局 `/interrupt` 干扰其它任务。执行状态保存 prompt_id，应用重启后仅续查原任务；队列和历史中都找不到任务时明确失败，不自动重发。默认模型不自动切换，也不会因本地不可达而转用远程。

实现参考 [ComfyUI 官方通信接口](https://docs.comfy.org/development/comfyui-server/comms_routes)，使用 `/system_stats`、`/object_info/{class}`、`/upload/image`、`/prompt`、`/history/{prompt_id}`、`/queue` 和 `/view`。


### NAS 多人隔离部署

使用 [NAS 独立工作区方案](deploy/nas/README.md)，每人一组 musecanvas + muse2api 容器及独立入口，分别登录、绑定自己的 Muse 账号和 API 密钥。**这不是一个共享实例里的多个用户**；不共享账号池、Cookie、浏览器 profile、数据库、模型配置或数据卷。生成器：

```sh
node deploy/nas/create-instance.mjs --name alice --email alice@example.com --port 8788 --url https://alice.canvas.example.com
```

进入生成目录，查看 `.env` 中的专属初始密码，再执行 `docker compose up -d --build`。muse2api 和浏览器调试端口不对 NAS 发布。ACCESS_MODE=account 只接受实例指定邮箱，禁止本机免登录与注册，私有媒体需登录，含其它用户邮箱的旧库拒绝启动。原桌面 ACCESS_MODE=local 保持免登录；不要把桌面模式直接暴露到 NAS 网络供多人使用。

工作区登录密码可在「设置 → 账号」修改。NAS 反向代理、资源及 ComfyUI 地址注意事项见部署说明。配置已进行双实例应用隔离与 Compose 校验，尚需在目标 NAS 实际构建运行。
